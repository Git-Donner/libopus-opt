`689522b99cf2aa1a4bdb55137b7e9f9a2447ef3446da78873766ef24c8976565`。
独立代码审查检查了数组边界、谓词、四路累计顺序、归约和符号恢复，未发现问题。

工具：AArch64 GCC 14.2、QEMU 10.0.13；沿用上次已验证并保存在用户目录的工具链。
QEMU CPU 为 `max,sve-max-vq=4`；无 SVE 测试为 `max,sve=off`。

| 禁用收缩的真实编码 | 同上 300 组配对帧及 11,241 次有效 SVE256 入口调用，结果一致 |

| 无 SVE | 11,344 算子用例与 300 组配对帧通过，SVE 入口调用为0 |
| UBSan | 当前 SVE 内核、包装器、NEON 对照和测试程序插桩；12,352 用例通过，无诊断，不声称整库均插桩 |
| CMake 构建 | 当前普通 `-O3 -march=armv8.2-a+sve -fno-semantic-interposition -fvisibility=hidden` 构建成功；交叉编译不使用宿主机 mtune=native |
| Autotools 构建 | 更新源文件后生成新静态库，再独立运行 12,352 算子和 300 配对帧，均通过；其参考构建使用禁用收缩配置，因此本次给内核增加了 NO_FMA 宏 |

长度为上一版相同的 27 种 N=2..256 测试长度，含非4/8倍数；K=0..1024。
输入含归一化随机、符号、零、负零、极小值、subnormal、等分数、稀疏向量及异常投影防御。
其中 12,348 用例直接调用 SVE 入口并逐字节对照，另4例检查投影防御不变式。
编码覆盖 mono/stereo、48kHz、2.5/10/20ms、每通道64kbit/s、complexity=5。

普通 O3 新代码使用显式 SVE FMLA；禁止收缩配置要使用 NO_FMA 开关。
二者分别与匹配配置的 NEON 比较，不声称两种不同配置的输出彼此完全相同。

源码已无 arm_neon.h、NEON 类型或 NEON intrinsics。
反汇编确认 FRECPE/FRECPS、FCVTZS、FMLA、TBL、归约、符号恢复和受谓词控制的加载存储均为 SVE。

不是源码保留了 NEON 运算实现。没有为消除这一条清零指令改写标量算法。
