# 本次实现验证

验证对象为本目录的 v2 六场景实现，基于仓库提交 9d4f11c3 的 Opus 源码。

当前云环境是 Linux x86-64、GCC 14.2.0；使用允许集合内的逻辑 CPU 0。下列结果证明框架行为和路径覆盖，不代表用户 ARM 机器上的性能。

## 完整默认配置

使用 configs/six_scenarios.json：每个场景100帧预热、1000帧测量、7次独立运行，六个场景全部通过。

独立验证 worker 的测量区调用计数如下（预热和计时外检查不包含在计数内）：

| 场景 | silk_Encode | CELT encode | silk_Decode | CELT decode |
|---|---:|---:|---:|---:|
| SILK encode | 1000 | 0 | 0 | 0 |
| SILK decode | 0 | 0 | 1000 | 0 |
| CELT encode | 0 | 1000 | 0 | 0 |
| CELT decode | 0 | 0 | 0 | 1000 |
| HYBRID encode | 1000 | 1000 | 0 | 0 |
| HYBRID decode | 0 | 0 | 1000 | 1000 |

每个测量包均通过模式、带宽、声道和时长检查。计时 worker 不包含调用包装；其输入、包和重建输出哈希与验证 worker 一致。

额外构建了定点版本，同样完成六个场景各1000帧的调用覆盖验证，解码复用了浮点基线生成的固定码流。也验证了中等码率双声道用例。当前实例未执行 ARM 原生测试。

## 回归检查

`make OPUS_DIR=/workspace/libopus-opt OPUS_BUILD_DIR=/workspace/opus-build check`：9项测试全部通过，包含多个参数化子检查：

- 六场景实际算子调用、对向阶段调用为零、帧数与时间求和一致。
- 未知字段、零帧、布尔值代替整数、拼错操作、非法声道/帧长、重复用例名和截断 JSON 被拒绝。
- 缺少 CPU 或指定不允许的 CPU 被拒绝。
- 缺失解码语料不会被默默生成；损坏语料被拒绝。
- 复制启动包后能够独立运行；重复输出不会覆盖；输入哈希稳定。
- 加速比与耗时下降区分、A/A区间、明确回退及重复次数不足的统计处理。

独立检查还覆盖了语料截断、尾随数据、单比特损坏；原生 worker 的短用例通过 ASan/UBSan 与严格编译告警检查。

## 比较流程

两份相同可执行包使用同一配置/语料，完整跑通六场景、两对 AB/BA 运行。由于少于5对，全部结果明确标为 insufficient，未据噪声判断为提速。

这是一项比较流程检查，不用于证明 A/A 在所有环境、次数或显著性门槛下绝不出现误判。正式性能研究需在目标机器上控制争用和频率，使用更多配对运行并检查原始数据与警示。
