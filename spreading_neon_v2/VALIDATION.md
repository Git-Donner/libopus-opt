# 验证记录（2026-11-16）

环境：AArch64 GCC14.2、QEMU10.0.13。没有原生目标ARM CPU性能数据。
模拟器用于正确性，不将其运行时间作为加速证据。

## 独立开关矩阵

| CUTOFFS / VECTOR_FINISH | 新边界谓词检验 | 统计/完整判决/历史状态 | 真实CELT配对编码 |
|---|---|---|---|
| 0 / 0 | 5,162,040通过 | 643,200通过 | 300组通过 |
| 1 / 0 | 5,162,040通过 | 643,200通过 | 300组通过 |
| 0 / 1 | 5,162,040通过 | 643,200通过 | 300组通过 |
| 1 / 1 | 5,162,040通过 | 643,200通过 | 300组通过 |

表的边界检验在每个配置都执行，用于检查同一份只读数据；不代表00会启用阈值路径。
实际算法选择另外通过四份反汇编核对：00无FABS/FPCR/ADDP，10有FABS/FPCR，01有ADDP，11两项都有。
11的真实编码QEMU指令跟踪也到达了FABS和向量ADDP块，并且编码配对仍通过。

每个643,200用例集覆盖四种舍入模式、N9..209、两种update_hf、单/双声道、不同前缀和
50种输入分布；6,432组guard-page序列检测越界。
精确阈值检验包含每个边界两侧4096个ULP、每种标准N的65536个随机位模式、正负零、
NaN/Inf、极大/极小值。非默认舍入时扫描器回退原乘法，比较完整统计和历史状态。
测试结束恢复原浮点环境，不比较FPSR粘滞异常标志的产生轨迹。

真实编码配置：mono/stereo，48kHz，2.5/10/20ms，每通道64kbit/s，complexity5。
每个变体所有packet、解码PCM和final range与冻结的原统计扫描一致；每条NEON/参考路径均
实际扫描296次，处理165,384个系数。包装器只用于功能证明，不进入性能计时构建。

## 阈值依据

原表达式在固定N和正输入下为单调函数。选取第一次使原两次RN32乘法结果大于等于T的
float32输入a；通过a及其前一个float的结果与单调性证明整个有限输入分类边界。
负数使用绝对值，NaN的有序比较为false，Inf不小于有限边界，正负零满足三个条件。
这不是把未经修正的sqrt(T/N)直接作为阈值。

两个独立的整数binary32舍入模型核对全部45个边界及指数缩放，一个执行5,898,285次
近边界检查，另一个执行3,687,390次检查；实际AArch64浮点测试额外验证上述5,162,040个谓词。
证明和脚本位于validation/，没有声称逐一执行过全部2^32个输入位模式。

## 性能边界

本轮减少的是每批数据的乘法依赖和频带末尾的标量搬运。
它增加了每次扫描的FPCR检查，以及阈值查表、分支、常量准备，代码体积也会增长。
小频带或特定处理器上可能无收益或回退，必须分别测10、01和11。
QEMU时间、已通过的功能用例数量以及静态指令减少都不能证明目标CPU加速。

现有分派接口、PVQ NEON/SVE、历史状态尾部、频带/声道次序及每频带整数除法均未修改。
ARM32、Windows/MSVC和启用fast-math的组合未做运行验证；不满足截止表条件时保留旧算术路径。
